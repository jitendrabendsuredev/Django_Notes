Chapter 1

What is Django?

You will learn: what Django is and how a web page request travels through it.

Django is a free, open-source Python web framework. A framework provides ready-made parts (URL routing, database access, admin panel, security) so you do not build everything from scratch.

MVT pattern

PartMeaningFile
ModelData (database table)models.py
ViewPython logic: takes a request, returns a responseviews.py
TemplateHTML page shown to the usertemplates/

Request flow

Browser→urls.py→View→Model→View→Template→Browser

Example: user opens /. urls.py finds the view. The view reads students from the database (Model) and passes them to the Template. The Template becomes HTML and the browser shows it.

Key points
  • Django = Python web framework.
  • MVT = Model, View, Template.
  • Every page follows: URL → View → Template.
Check yourself

Q1. What does MVT stand for?
Answer: Model, View, Template.

Q2. Which part contains the Python logic?
Answer: The View (views.py).

Chapter 3

URL and View: Your First Page

You will learn: how a URL is connected to a view function.

View = a Python function that receives request and returns a response.

students/views.py
from django.http import HttpResponse

def home(request):
    return HttpResponse("Hello, Django!")

URL = connects an address to a view. First create students/urls.py:

students/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
]

Then include it in the project's urls.py:

mysite/urls.py
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('students.urls')),
]
name='home' is a nickname for the URL. Later we use it in templates as {% url 'home' %} instead of typing the address.
Key points
  • View = function(request) that returns a response.
  • path(address, view, name) connects URL and view.
  • include() connects app urls to the project urls.
Check yourself

Q1. What does path("", views.home) mean?
Answer: When the address is empty (home page), run the home view.

Q2. Why give a URL a name?
Answer: To use it later with {% url %} so links never break.

Chapter 4

Templates and Variables

You will learn: how to return an HTML page and show Python data in it.

A template is an HTML file that can contain Django code. The template engine fills in the values and sends plain HTML to the browser.

Step 1: Send data from the view

students/views.py
from django.shortcuts import render

def home(request):
    context = {'name': 'Riya', 'marks': 82}
    return render(request, 'students/home.html', context)

render(request, template_name, context) loads the HTML file and fills it with the values of the context dictionary.

Step 2: Use the data in the template

Save at students/templates/students/home.html:

html
<h1>Hello {{ name }}</h1>
<p>Your marks: {{ marks }}</p>
SyntaxNameUseExample
{{ }}VariablePrint a value{{ student.name }}
{% %}TagLogic (if, for, url, csrf){% if marks > 35 %}
{# #}CommentNot shown in browser{# note #}
Key points
  • Templates live in app/templates/app/.
  • The context dictionary key becomes the variable name.
  • Dot notation reads a field: {{ student.name }}.
Check yourself

Q1. How do you print a variable?
Answer: {{ variable }}

Q2. What is the context?
Answer: A dictionary of data sent from the view to the template.

Chapter 5

Static Files (CSS, Images)

You will learn: how to add CSS and images to a template.

Files that do not change (CSS, images, JavaScript) are static files. Keep them inside students/static/.

html
{% load static %}
<!DOCTYPE html>
<html>
<head>
    <link rel="stylesheet" href="{% static 'css/style.css' %}">
</head>
<body>
    <img src="{% static 'images/logo.png' %}" width="100">
</body>
</html>
  • {% load static %} is written once at the top of the template.
  • {% static 'css/style.css' %} gives the correct URL of students/static/css/style.css.
Key points
  • Put CSS/images in the app's static/ folder.
  • Always write {% load static %} first.
  • Use {% static 'path' %} instead of a normal path.
Check yourself

Q1. Which tag must come before using {% static %}?
Answer: {% load static %}

Q2. Where do CSS files go?
Answer: students/static/css/

Chapter 6

Template Tags: if, for, Filters

You will learn: how to show content conditionally and repeat HTML for a list.

if / elif / else

Every {% if %} must end with {% endif %}.

html
{% if marks >= 75 %}
    <p>Distinction</p>
{% elif marks >= 35 %}
    <p>Pass</p>
{% else %}
    <p>Fail</p>
{% endif %}

for loop

Repeats HTML for every item of a list. Must end with {% endfor %}.

html
<ul>
  {% for s in students %}
      <li>{{ s.name }} - {{ s.course }}</li>
  {% endfor %}
</ul>

s is one student in each round. s.name reads that student's field.

Filters

FilterExampleResult
upper{{ name|upper }}RIYA
title{{ name|title }}Riya Patil
default{{ phone|default:"Not given" }}Not given (if empty)
length{{ students|length }}Number of items
Key points
  • {% if %} needs {% endif %}; {% for %} needs {% endfor %}.
  • The loop variable (s) holds one item per round.
  • Filters change how a value looks: {{ value|filter }}.
Check yourself

Q1. Which tag closes a for loop?
Answer: {% endfor %}

Q2. Write code to print a name in capital letters.
Answer: {{ name|upper }}

Chapter 7

Models, Migrations and Admin

You will learn: how to create database tables using Python classes.

A model is a Python class that becomes a database table. Each attribute becomes a column. The ORM lets you use the database with Python code instead of SQL.

students/models.py
from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()
    course = models.CharField(max_length=50)

    def __str__(self):
        return self.name
FieldStores
CharField(max_length=n)Short text
IntegerField()Whole number
EmailField()Email (format checked)

Only a few fields are shown here. The full list of data types is in the next chapter.

__str__ decides how an object is shown (for example in admin). Django adds an id column automatically.

Migrations: create the table

terminal
python manage.py makemigrations
python manage.py migrate

makemigrations prepares the change. migrate applies it to the database. Run both every time you create or change a model.

Admin panel (add data quickly)

students/admin.py
from django.contrib import admin
from .models import Student

admin.site.register(Student)
terminal
python manage.py createsuperuser
python manage.py runserver
# open http://127.0.0.1:8000/admin/ and add 2-3 students
Key points
  • Model class = table, attribute = column.
  • After every model change: makemigrations, then migrate.
  • Register the model in admin.py to manage data in /admin/.
Check yourself

Q1. Which two commands create the table?
Answer: makemigrations and migrate

Q2. What does __str__ do?
Answer: Decides how the object is displayed as text.

class Course(models.Model):

One model with many data types

students/models.py
from django.db import models

class Student(models.Model):
    GENDER_CHOICES = [
        ('M', 'Male'),
        ('F', 'Female'),
    ]

    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
    age = models.IntegerField()
    percentage = models.FloatField(default=0)
    fees = models.DecimalField(max_digits=8, decimal_places=2)
    gender = models.CharField(max_length=1, choices=GENDER_CHOICES)
    is_active = models.BooleanField(default=True)
    birth_date = models.DateField(null=True, blank=True)
    address = models.TextField(blank=True)
    photo = models.ImageField(upload_to='photos/', blank=True)
    created = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.name

{% else %}

{% endif %}
  • date:"d M Y" filter shows a date as 12 Oct 2026.
  • get_gender_display shows the readable label (Male) of a field that has choices.
  • A BooleanField is used directly in {% if %}.

Changing a model later: if you add a new field to a table that already has data, Django asks for a default value (or the field must have null=True / default=...). Then run makemigrations and migrate again.
Key points
  • Choose the field type by the kind of data: text, number, true/false, date, file, link to another table.
  • CharField needs max_length; DecimalField needs max_digits and decimal_places.
  • null=True is for the database, blank=True is for forms/admin validation.
  • Use choices for a fixed list of values, default for a starting value.
  • After adding or changing any field: makemigrations then migrate.
Check yourself

Q1. Which field stores True/False?
Answer: BooleanField

Q2. Which field is best for price (like 499.50)?
Answer: DecimalField(max_digits=8, decimal_places=2)

Q3. Difference between null=True and blank=True?
Answer: null=True lets the database column store NULL; blank=True lets the form/admin accept an empty value.

Answer: auto_now_add=True

Chapter 9

Show Database Data in HTML (Read)

You will learn: how to fetch records and display them in a table.

This is the R of CRUD. First fetch the data in the view:

students/views.py
from django.shortcuts import render, redirect, get_object_or_404
from .models import Student

def student_list(request):
    students = Student.objects.all()
    return render(request, 'students/list.html', {'students': students})

Student.objects.all() returns every row of the table. Then show it with a for loop:

students/templates/students/list.html
<h1>Students</h1>

{% if students %}
<table border="1" cellpadding="6">
    <tr><th>Name</th><th>Age</th><th>Email</th><th>Course</th></tr>
    {% for s in students %}
    <tr>
        <td>{{ s.name }}</td>
        <td>{{ s.age }}</td>
        <td>{{ s.email }}</td>
        <td>{{ s.course }}</td>
    </tr>
    {% endfor %}
</table>
{% else %}
    <p>No students yet.</p>
{% endif %}

Do not forget the URL in students/urls.py: path('', views.student_list, name='student_list')

Other ways to read data

python
Student.objects.all()                    # every row
Student.objects.get(id=1)                # exactly one row
Student.objects.filter(course='Python')  # rows that match
Student.objects.filter(age__gte=18)      # age >= 18
Student.objects.order_by('name')         # sorted by name
Student.objects.count()                  # number of rows
Key points
  • Model.objects.all() = all rows.
  • Send them to the template in the context dictionary.
  • Use {% for %} in the template to display each row.
Check yourself

Q1. Which line fetches all students?
Answer: Student.objects.all()

Q2. What is the difference between get() and filter()?
Answer: get() returns exactly one object; filter() returns a list of matching objects.

Chapter 11

Create: Add a Record

You will learn: how to take data from an HTML form and save it in the database.

View

students/views.py
def student_add(request):
    if request.method == 'POST':
        Student.objects.create(
            name=request.POST['name'],
            age=request.POST['age'],
            email=request.POST['email'],
            course=request.POST['course'],
        )
        return redirect('student_list')
    return render(request, 'students/form.html')
  • request.method is GET when the page is opened and POST when the form is submitted.
  • request.POST['name'] reads the input whose name="name".
  • redirect('student_list') sends the user back to the list after saving.

Template (form.html)

We use one form for both Add and Edit:

students/templates/students/form.html
<h1>{% if student %}Edit{% else %}Add{% endif %} Student</h1>

<form method="post">
    {% csrf_token %}
    <p>Name: <input type="text" name="name" value="{{ student.name }}" required></p>
    <p>Age: <input type="number" name="age" value="{{ student.age }}" required></p>
    <p>Email: <input type="email" name="email" value="{{ student.email }}" required></p>
    <p>Course: <input type="text" name="course" value="{{ student.course }}" required></p>
    <button type="submit">Save</button>
</form>
<a href="{% url 'student_list' %}">Back</a>
{% csrf_token %} is required inside every POST form. Without it Django shows 403 Forbidden.
Key points
  • Form method="post" + {% csrf_token %}.
  • Input name attribute = key in request.POST.
  • After saving, use redirect().
Check yourself

Q1. Why is csrf_token needed?
Answer: It protects the form from fake submissions; without it Django gives a 403 error.

Q2. How do you read a form value in the view?
Answer: request.POST["fieldname"]

Chapter 12

Update: Edit a Record

You will learn: how to load an existing record into the form and save the changes.

students/views.py
def student_edit(request, id):
    student = get_object_or_404(Student, id=id)
    if request.method == 'POST':
        student.name = request.POST['name']
        student.age = request.POST['age']
        student.email = request.POST['email']
        student.course = request.POST['course']
        student.save()
        return redirect('student_list')
    return render(request, 'students/form.html', {'student': student})
LineMeaning
get_object_or_404(Student, id=id)Finds the student with that id. If none exists, shows a 404 page instead of crashing.
GET requestSends the student to form.html, so boxes are pre-filled using value="{{ student.name }}".
POST requestChanges the fields with new values, then save() writes them to the database.
If you forget student.save(), nothing changes in the database.
Key points
  • Fetch the object with get_object_or_404.
  • Change the fields, then call save().
  • The same form.html is reused; {% if student %} shows the Edit title.
Check yourself

Q1. What happens if you forget save()?
Answer: The database is not updated.

Q2. Why use get_object_or_404?
Answer: To show a 404 page when the id does not exist.

Chapter 13

Delete: Remove a Record

You will learn: how to delete a record safely with a confirmation page.

students/views.py
def student_delete(request, id):
    student = get_object_or_404(Student, id=id)
    if request.method == 'POST':
        student.delete()
        return redirect('student_list')
    return render(request, 'students/confirm_delete.html', {'student': student})
students/templates/students/confirm_delete.html
<h1>Delete Student</h1>
<p>Are you sure you want to delete <b>{{ student.name }}</b>?</p>

<form method="post">
    {% csrf_token %}
    <button type="submit">Yes, Delete</button>
    <a href="{% url 'student_list' %}">Cancel</a>
</form>
Delete uses a POST form with a confirmation page, not a plain link. A link can be opened by mistake; a POST needs an intentional click.

Test your project (in this order)

  1. Open / and check the list.
  2. Click Add Student, save, check the list.
  3. Click Edit, change a value, save.
  4. Click Delete, confirm.
Key points
  • obj.delete() removes the record.
  • Ask for confirmation first (POST form).
  • All four operations now work: Create, Read, Update, Delete.
Check yourself

Q1. Which method removes a record?
Answer: student.delete()

Q2. Why not delete using a simple link?
Answer: A link can be clicked or opened by mistake; POST is safer.
